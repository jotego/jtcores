# jt51 register-program comparison

Runs the exact bytecode used by the PCB monitor against the checked-out jt51
RTL. It uses normal synthesis logic, waits for busy, records each native chip
sample and exports both quantized and full-resolution outputs. CPU delay-loop
timing is deliberately approximate. Steady tone and status comparisons use the
original interface below; event captures support envelope-duration measurements
without claiming exact alignment with the CPU's physical bus timing.

```
bash tasks/jtcores-143/ver/jt51/sim.sh PROGRAM.bin OUTPUT.csv [SAMPLES]
```

Requires root `setprj.sh` and Verilator on PATH. The workstation's compatibility
wrapper handles the old Verilator `--quiet` option. Outputs are created
exclusively; use a fresh name per run. `--keep` adds `test.fst` alongside the CSV
with actual nominal 3.58 MHz clock timing. No trace is generated by default.

For a transient capture, use an initialization program with no key-on, followed
by an event program containing a delay and key-on:

```
bash tasks/jtcores-143/ver/jt51/sim.sh --event INIT.bin EVENT.bin OUTPUT.csv [SAMPLES]
```

INIT executes with recording off, then settles for 4096 master clocks. Recording
starts before EVENT executes and continues during its writes, busy waits and
delay opcodes, then until the requested native sample count (default 16384).
CSV rows retain their 64-master-clock native cadence. If EVENT runs longer than
the capture window, it still completes, but additional sample rows are suppressed.

Event mode exclusively creates `OUTPUT.csv.events.csv` as well as the sample
CSV. Its columns are `kind,clock,reg,value`. `capture_start` records the master
clock at which capture is armed; `write` records the beginning of the jt51 data
write strobe, with decimal register/value fields. Only EVENT writes are logged.
This is a logical driver timestamp, not an assertion of exact internal latch or
PCB CPU-write timing. Sidecar events can occur after the last captured sample.
The CSV clock origin includes the harness reset/startup cycles and is not shared
with the external-model clock origin. Delay bytecodes remain approximately
32 master clocks per count; compare envelope durations and levels after the
observed event rather than matching absolute sample indices across devices.
