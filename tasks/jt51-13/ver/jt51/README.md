# jt51 register-program comparison

Runs the exact bytecode used by the PCB monitor against the checked-out jt51
RTL. It uses normal synthesis logic, waits for busy, records native chip
samples and exports both quantized and full-resolution outputs. CPU delay-loop
timing is deliberately approximate. Steady tone and status comparisons use the
original interface below; event captures support envelope-duration measurements
without claiming exact alignment with the CPU's physical bus timing.

```
bash tasks/jt51-13/ver/jt51/sim.sh PROGRAM.bin OUTPUT.csv [SAMPLES]
```

Requires root `setprj.sh` and Verilator on PATH. The workstation's compatibility
wrapper handles the old Verilator `--quiet` option. Outputs are created
exclusively; use a fresh name per run. `--keep` adds `test.fst` alongside the CSV
with actual nominal 3.58 MHz clock timing. No trace is generated by default.

Optional `--stride N`, before the program arguments, retains every Nth native
stereo frame, with N from 1 to 1024 and default 1. Both legacy and event modes
accept it; `--keep`, when used, remains the first option:

```
bash tasks/jt51-13/ver/jt51/sim.sh --stride 1024 PROGRAM.bin OUTPUT.csv 16384
bash tasks/jt51-13/ver/jt51/sim.sh --stride 3 --event INIT.bin EVENT.bin OUTPUT.csv 1024
```

The first retained native frame has index 0, followed by N, 2N, and so on.
CSV `sample` numbers count retained frames from zero. `SAMPLES` counts retained
stereo frames, and their `clock` timestamps remain actual master-clock counts,
spaced by 64*N clocks. Every intervening model clock and EVENT instruction still
executes. The recorded rate is 55,937.5/N Hz at the specified 3.58 MHz clock;
this defines the interval and does not align its phase with the PCB.
The existing sample-count bound is 10,000,000, with an additional bound of
SAMPLES*N <= 16,777,216 native frames. Thus 16,384 frames at stride 1024 covers
about 300 seconds without a large CSV. Default stride 1 preserves existing
sample files and event sidecars byte for byte for the same inputs.

For a transient capture, use an initialization program with no key-on, followed
by an event program containing a delay and key-on:

```
bash tasks/jt51-13/ver/jt51/sim.sh --event INIT.bin EVENT.bin OUTPUT.csv [SAMPLES]
```

INIT executes with recording off, then settles for 4096 master clocks. Recording
starts before EVENT executes and continues during its writes, busy waits and
delay opcodes, then until the requested native sample count (default 16384).
Default CSV rows retain their 64-master-clock native cadence. If EVENT runs longer than
the capture window, it still completes, but additional sample rows are suppressed.

Event mode exclusively creates `OUTPUT.csv.events.csv` as well as the sample
CSV. Its columns are `kind,clock,reg,value`. `capture_start` records the master
clock at which capture is armed; `write` records the beginning of the jt51 data
write strobe, with decimal register/value fields. Only EVENT writes are logged.
This is a logical driver timestamp, not an assertion of exact internal latch or
PCB CPU-write timing. Sidecar events can occur after the last captured sample.
The CSV clock origin includes the harness reset/startup cycles and is not shared
with the external-model clock origin. Delay bytecodes remain approximately
32 master clocks per count; compare envelope durations and levels after the
observed event rather than matching absolute sample indices across devices.

Optional public key-on timing diagnostics precede `--stride` (and follow
`--keep`): `--keyon-phase P` inserts0..63 master clocks before each nonzero
register08 data strobe so its assertion clock has residue P modulo64. It
implies `--public-bus`, which can also be used alone without changing timing.
Both options create `OUTPUT.csv.bus.csv` exclusively. The log includes INIT
and EVENT data assertions/releases, assigned public pin values and status;
`cen_p1_scheduled` is the parity scheduled for the upcoming evaluation, not
an independently sampled prior pin. These timestamps do not establish internal
acceptance or the PCB's write phase. Omit both options to preserve the original
output files and timing. [Algorithm phase methods](../../plans/algorithm-measurements.md)
describe the finite64-residue experiment and its limits.

## Persistent history (new task only)

`sim.sh --history /ABS/HISTORY.tsv --delay-clocks 37.5 --stride N --event INIT EVENT CSV SAMPLES`
preloads and validates every input before constructing the chip or creating output.
TSV has the exact header `program\tgap_before_master_clocks`, followed by an
absolute monitor-program path and a nonnegative integer gap BEFORE that program.
Header-only means fresh control. Each program is at most 8192 bytes and must
end with END; the combined history/INIT/EVENT limit is 2,000,000 register writes.
No model reset occurs between programs. No implicit settle or capture alignment
occurs in history mode, including after the final history row or CLI INIT.
To settle target INIT explicitly, put it in history followed by an END-only row
whose gap specifies that interval; use END-only CLI INIT.

Delay counts accept only 32 (default) or 37.5 master clocks. Integer half-master
clock carry persists across all programs and manifest gaps. Execution floors
the cumulative requested interval to the model's step quantum: one master clock
for jt51, two for OPM. Residual carry is preserved, never independently rounded
per opcode. Fixed write/busy API timing remains model-specific. This approximates
the physical CPU delay loop; it does not establish accepted write phase or
convert MAME source cycles. Source-cycle/compiler policy is separate.

`CSV.history.csv` records each row's absolute program path, SHA256, write count,
clock before/gap/program/after, requested and executed gap, half-clock carry,
program delay accounting, and step quantum. INIT and capture_start rows expose
the zero implicit gap. These driver timestamps do not assert internal acceptance.
Existing public-bus logging can include the complete prefix; no extra OPM status
reads occur with that option off. Default no-history/32 timing and schemas are
retained. Existing sample and stride guards still apply.

Builds go only to `tasks/jt51-13/artifacts/model-history-validation`, never the
sealed baseline task. Requires OpenSSL development headers/libcrypto for input
SHA256 metadata. External emulator and RTL sources are read-only dependencies.
