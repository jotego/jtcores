# S18 passive YM7101 video interface

`ym7101` keeps `PASSIVE=0` and `MODE4=1` as defaults, preserving the original clock-phase path and full Mode 4 behavior for standalone users. The S18 wrapper instantiates `ym7101 #(.MODE4(0), .PASSIVE(1))`: its passive path is for Mode 5, H40, display-enabled 320×224 output with the noninterlaced S16 raster profile measured below. `MODE4=0` prunes selected Mode 4 graphics rendering paths for S18 Pocket while retaining the real M5 state and CPU programming/control paths. It does not force the VDP into Mode 5 or remove every Mode 4 path.

The attached S18 VRAM keeps `SERIAL_LOOKAHEAD=0` as its default. The wrapper enables it only for its passive YM instance because at the shortened 384-pixel line cadence the first serial clock can follow a page load on the next MCLK; the existing synchronous serial-read register otherwise presents the previous page's byte for that first transfer. The option selects the already latched DRAM address for that same synchronous read on the page-load edge. It does not add a read port or change the clock, SC sequence, page-load priority, or legacy default-off behavior. The default `PASSIVE=0` and legacy fixtures retain the historical serial-read timing.

## Clocks, sync, and blanking

The synthesized S18 video and YM logic use `clk48`/`MCLK` at 48 MHz. The S16 timer and raster tracker advance on synchronous clock enables: `pxl_cen` is 6 MHz (one pulse per eight 48 MHz clocks) and `pxl2_cen` is 12 MHz (one pulse per four clocks). In the S18 wrapper, `pxl_48cen` and `pxl2_48cen` carry those same 6/12 MHz enables into the passive YM path. They are enables on the 48 MHz clock, not separate clocks. `MCLK_e` is a sampled enable/control input; YM storage flops remain clocked on `MCLK`.

The S16 timer drives active-high HS and VS sync pulses and active-high LHBL/LVBL visible-region levels. Raw HS/VS continue to feed the S16 object scanner and the VDP; LHBL/LVBL feed both video engines. The external S18 HS/VS use native centered phases selected from the timer's committed raster mode: H+4/V-4 for 400×262 and H+7/V-4 for 384×260, matching the former 320-wide MiSTer OSD offsets. This moves only the output sync edges; raw raster counters, blanking, sprite origin, VDP timing, and rendering coordinates retain their original phase. The raster tracker measures the raw HS/VS rising edges and active-region transitions of LHBL/LVBL. YM `YS` qualifies an opaque VDP pixel when high; `YS=0` is transparent to the S18 mixer.

MiSTer and SiDi128 users with saved nonzero H/V OSD offsets should set them to zero after updating, so the native centering is not applied twice.

The tracker measures input timing instead of assuming a fixed S16 timer phase. It requires stable pixel-enable cadence and phase, HS/LHBL line period and relative offset, VS/LVBL vertical offset, frame length, active width, and active height. A timing or phase fault clears `locked`/`geometry_valid`; a later stable raster can reacquire them.

## Passive render profile

The passive path accepts measured horizontal totals of 400 or 384 pixels, a 320-pixel active width, 260–262 lines per frame, 224 active lines, and no raster phase error. It also requires Mode 5 (`reg_m5`), H40 (`reg_rs1`), and display enable (`reg_disp`) before setting renderer-ready. The noninterlaced 320×224 profile is the supported contract; this is not a claim of interlace support. The acceptance logic is based on measured raster geometry plus Mode 5/H40/display controls, rather than a general implementation of all YM7101 register-mode combinations.

At a nominal 6.000 MHz pixel enable, the validated raster variants have these calculated totals and refresh rates. Actual PLL frequency can differ slightly from nominal.

| Raster | Pixels per line | Lines per frame | Line period | Frame rate |
| --- | ---: | ---: | ---: | ---: |
| 400×262 | 400 | 262 | 66.6667 µs | 57.2519 Hz |
| 384×260 | 384 | 260 | 64.0000 µs | 60.0962 Hz |
| 384×261 | 384 | 261 | 64.0000 µs | 59.8659 Hz |

384×261 remains a synthetic diagnostic profile only. Production S18 supports the 384×260 fast profile and 400×262 original profile; it does not expose 384×261.

## Production S18 timing selection

MiSTer and SiDi128 default to **60 Hz**: the S18 production S16 timer starts in
384×260 mode (nominal 60.10 Hz) and the OSD's **Original 57 Hz** choice selects
400×262 (about 57.25 Hz). The `CORE_OSD` option is enabled only for these two
targets; its `OE` selector uses `status[14]`, with zero selecting the default
fast mode and one selecting original timing. Pocket has no timing OSD option:
its build does not define `DUAL_RATE`, so the static original timer runs at
400×262 from power-up. The configured master clock and enables remain fixed at
48 MHz, 6 MHz (`pxl_cen`), and 12 MHz (`pxl2_cen`) in either profile.

The dual-rate S16 timer commits a changed request only at the H511/vdump224
line boundary while LVBL is low. It changes the next line start on that same
enable; neither the VDP nor the S16 pipeline is reset, and no MMR rewrite is
needed. The passive YM mutes while the measured geometry is invalid, reacquires
the new raster, completes its native 420-event prime, and resumes with the
profile's 72-event (384×260) or 40-event (400×262) blanking quota.

The renderer preserves the legacy 420-step H traversal. Its accelerated blank-phase quota is `(420 - measured_line_pixels) × 2`: 40 for the 400-pixel line and 72 for the 384-pixel line. It primes the vertical seed and V0 state before the first active origin; readiness is published at active H26/V0 after those commits. Until ready, when display or Mode 5/H40 is disabled, or when geometry changes, passive YS and DAC RGB are muted. A continuing accepted raster can lock and prime again after the cause is removed.

The `jts18_vdp` boundary pipelines `{YS, RGB}` together in two 25-bit registers. Both stages use `clk48` and advance on the 6 MHz `pxl_48cen` enable; they are alignment registers in the same clock domain, not CDC synchronizers. Reset clears both stages on a `clk48` edge even if the pixel enable is low. The active-low reset presented to the YM is also registered synchronously on `clk48`, avoiding a half-cycle reset launch path. The pipeline carries transparent and blank tuples normally. After raw YM invalidation, zero reaches the wrapper output by the second subsequent enabled capture (up to 16 `clk48` periods while the enable continues). The S18 color mixer and video tail retain their original framework 6/12 MHz enables and the raw S16 blank signals. The corrected S18 timing constraints contain no blanket YM/VRAM multicycle exception; related 96/48 MHz PLL clocks remain synchronously analyzed.

The CPU VDP wait qualification is separate from video phase handling: `jts18_main` passes `vdp_cs` to `jtframe_68kdtack_cen.bus_legit`, so a VDP DTACK wait is treated as a legitimate board wait while normal CPU phase cadence and the existing wait-recovery overflow assertion remain in place.
