# 1B11140 Z80µP VIDEO board digest

5 sheets, P82-003/A/M3, 17.5.1983. Connectors: CN1 (50-pin, to I/O board),
CN2 (to ROM module: AF address out, D0..D23 pixel data in).

## Sheet 1/5 — clocks, counters, sync, palette, RGB out

Clock generation:
- QZ 18.432MHz crystal oscillator built from LS368 inverters (2N) + R1/R2 330R + C2 100pF.
- 2M LS107 (dual JK) divides 18.432 by 3 -> 6MHz pixel clock. Distributed as
  `6MHz (SH2-3-4)`, inverted `/6MHz (SH3-4)` via LS368 2N, and `CLK (SH3)`.

Horizontal chain: 2L LS74 (1H) -> 3L, 4L LS161 -> 2H..256H. Presets (traced):
3L /LOAD=VCC (free runs, A-D=GND), 4L A,B,D=GND C=VCC -> upper counter reloads
at 4, so 384 clocks/line; 256H=1 during the 256 display clocks.
- `1Hµ` = 1H buffered by LS368 2N pin14->13, goes to CN1-26: this is the Z80 clock
  on the I/O board (3.072MHz = 6.144/2... see io digest; MAME says 18.432/6 = 3.072MHz).
- HBLANK flop (5M-2, traced): D=5L NAND(8H,16H,32H,64H), CK=2H, /CLR=256H, /PRE=VCC.
  Q=1 (video owns the RAMs) H~258..505 except an 8-clock CPU slot at H~378..385;
  Q=0 through H 506..257. Feeds the I/O board /WAIT (CPU bus grant), not the monitor.
- /LD1, /LD2 tile-fetch load strobes: 5N LS10 + 5K LS04 from 1H,2H,4H phases.

Vertical chain: 2L LS74 (1V) + 3N, 4N LS161 -> 2V..256V. Presets (traced):
3N A,B=GND C,D=VCC; 4N A,B,C=VCC D=GND -> reload value 248, so 264 lines/frame.
/VSYNC = 256V (4N pin 11, QD) directly: low for counter 248..255, i.e. the 8
lines right before active video. Display = counter 256..479 (224 lines).
- VBLANK: 5N LS10 NAND(128V,64V,32V) with 16V into 5P LS74 latch -> VBLANK (SH5)/(SH4).
- CBLANK*: 5H LS02 NOR(VBLANK, 256H-derived) -> composite blank.
- Sync flop (5M-1, traced): D=5J LS00 NAND(32H, 64H via 5K), CK=16H, /CLR=VCC;
  /PRE = 5K inversion of the /256H net, holding Q through the display half so only
  the H 160..191 window fires: /SYNCV low at H 176..207 (32 clocks). /Q clocks the
  V counters (2L toggles 1V; 3N/4N enabled every other line) at H=176.
  NOTE on naming: the net labelled /256H is HIGH during the display half
  (H 256..511) - pinned by four constraints: one sync/line, 264-line frame,
  256-px visible width (5H CBLANK*), and HCMP1* (5G: flip XOR active only in
  the display half).
- /CSYNC = /VSYNC & /SYNCV at 5G LS08 (all active low) -> 9M LS367 (R18 100R,
  R19 470R pullup) -> /SYNC out.
- CBLANK* (5H LS02, traced) = NOR(VBLANK, 256H). Note: the *-suffixed nets
  (256H*, HCMP1*, CBLANK*) are a distinct delayed/registered family - to be
  resolved in the pipeline pin walk.

Screen flip XOR banks (LS86):
- Vertical: 4P/3P XOR 1V..128V with VCMA (from I/O LS259, flip X in MAME terms is VCMA/HCMA
  — schematic: VCMA (SH5) into V XORs, HCMA (SH5) into 5G/HCMP1*) -> 1V'..128V'.
- Horizontal: 4M/3M XOR 8H..128H with HCMP1* -> 8H'..128H'.

Palette:
- 2× 82S131 (512x4 bipolar PROM) at 9F, 9G. Address A0..A8 driven by (via muxes on this sheet):
  SELOBJ (SH3) through LS02 8L gates, BK1/BK2 (SH5) bank bits, and the pixel/colour code lines.
- PROM outputs (8 bits total) latch into 9J LS374, CP = 6MHz, /OE = /VIDOUT (SH5).
- Resistor DAC per gun: B = R8 680R + R9 1K (loads R7 470R / to gnd),
  G = R10 820R + R12 1K2 (R13 390R), R = R5 820R + R4 1K + R6 1K2 (R3 390R).
  3 bits G? — exact bit-to-gun split: 9J outputs pins 2,5 -> B; 6,9(12?) -> G; 15,16,19 -> R
  with weights per resistor values (matches MAME resnet: 470/220... to verify in video.cpp).
- 9E, 9D LS157 muxes select between object pixel code (X1OUT..X6OUT) and background
  colour (COLOUT1..COLOUT6) using SELECT (SH6?) -> palette address; 6G LS02 + 6L LS00
  combine HBLANK/CBLANK for /VIDOUT gating.
- 9M LS367 also buffers CF1..CF4 (SH4) through R14..R17 onto RGB lines: background
  colour high bits driven directly (CF = colour attribute bits from tile attr RAM).

## Sheet 2/5 — background pixel pipeline

- ΣV adders: 1G, 1H LS283 add V' counter bits to per-column scroll value (from
  attribute RAM), producing ΣV1..ΣV8 (scrolled row). Latched in 1F LS374 (/VPL strobe SH4).
- 2G/2F LS175 + 2E LS86 + 2H LS20: comparator/checksum logic -> /CKOKVER, /DOKVER (SH4)
  (scroll/fetch handshake).
- Tile map RAM: 2A, 2B, 2C 2114 (3× 1K×4). Address: mux 1E/1D/1C LS157 select between
  CPU address AB0..AB9 (via /SABBKG) and video address (ΣV row + H column 32H'..128H', 64H').
  R/W from /WRBKGH, /WRBKGL (SH5); /VRHB, /VRLB write strobes via 3F LS08.
- CPU read path: 1A LS244 (nibble, BKB1/BKB2 high bits) and 1B LS245 (byte) -> DBB0..DBB7.
- 2114 outputs = tile code Σ0..Σ13 (10 bits code + attr nibble BKB) feeding:
  - 3C/3B/3A LS157: mux tile code vs CPU AB into ROM address AF3..AF12 (CN2 out).
  - 4H LS175 + 2J LS374: pixel-attribute pipeline (PAP0..3, HPLA0..7) -> colour/priority.
  - MPX select: 3G LS04 + 3H LS32 from 4H(x2?), 256H.
- Background ROMs on board: 4A (B3), 4C (B2), 4E (B1), each "2732 or 2764", address
  AF3..AF12 (+Σ0..Σ2 low bits, 26/27/28 jumpered), data D0..D23 (24-bit = 3 planes × 8 pix)
  also present on CN2 from the ROM module (board option — see 1b11147 digest).
- Pixel shifters: 12× LS194 4-bit bidirectional shift registers in 3 rows of 4:
  3D 3E 4F 4G (plane 0), 5A 5B 5C 5D (plane 1), 6A 6B 6C 6D (plane 2).
  Parallel load D0..D23, shift at 6MHz; direction pins driven by X1L/X1R .. X6L/X6R
  (flip). Serial outs -> x1..x6 taps (SH4) = 2 pixels × 3 planes (even/odd pixel streams
  S0T1/S1T1/S0T2/S1T2 select).

## Sheet 3/5 — object (sprite) line buffers

Two identical halves (buffer A / buffer B, ping-pong):
- H position counters: 7G+8G / 8H+7H LS161 pairs, preset from HPLA0..7 (object X),
  load /CNTLDT2 / /CNTLDT1, count at 6MHz; XOR banks 7F/8F / 8J/7J LS86 produce
  buffer addresses A0..A7 (flip-aware).
- Line buffer RAM: 2148H ×4 (7E, 7D / 7K, 7L) 1K×4, write strobes /CST2 / /CST1
  from 6G+6G LS27/LS02 (gated with ABDISP2/ABDISP1), R//WT2 / R//WT1 (SH5).
- 7A/8A, 7P/8P LS86: address XOR (display vs fill phase); 7C, 7M LS244 buffers;
  7B, 7N LS374 latch buffer output pixels.
- 8C, 8N 82S100 field-programmable PLAs (the two NO_DUMP proms2 in MAME!):
  inputs = latched buffer pixels (x1'..x6' / COL1'..COL6'), VBLANK, SELECT, 256Hx,
  ABDISP1/2, SELOBJ; outputs = X1OUT..X6OUT, COLOUT1..COLOUT6 (to palette mux on SH1)
  and /X456, /X123 (SH4, priority), via 8D LS27/LS27 gates.
- COL1..COL6 object colour lines in from SH4/SH1.

## Sheet 4/5 — control customs and object RAM

- CONTROL LOGIC 1 = 6J (20-pin custom/PAL, "CONTROL LOGIC 1"): inputs 1H 2H 4H,
  /ABLOAD, 256Hx, SELECT, 8H, /256H, 256H*; outputs /YA /YB (SH1? bank), /CNTLDT1,
  /CNTLDT2, /CNTLD, /CNTCLR (SH3 counters), LDCOL3H, BIT80 (via 6H buffer).
- CONTROL LOGIC 2 = 6K (20-pin custom/PAL): inputs 1H 2H 4H 8H /256H /ABT, /X456
  /X123 (SH3), SELECT, 256H*; outputs /COLL1 (collision!), /VPL (SH2), /OBDLOUT (SH2),
  /CKOKVER (SH2), LPREPF (via 6H), /LPFMSW.
  -> These two are the object-engine state machines (fetch/fill scheduling).
- 6P LS74: /ABT flop (1H vs /6MHz); 6N LS74 ×2: SELECT flop chain from /LD2, /256H
  -> SELECT (SH3-5); 6L LS00 + 16V/VBLANK gating -> 256Hx.
- 6M LS74 pair: /DOKVER//CKOKVER -> R//WT1, R//WT2 buffer-swap flip flops (with 5K
  LS04, 6L LS00, /6MHz) — ping-pong control.
- Object RAM: 1L, 1M 2114 (obj RAM 2×1K×4 = the 6840-68xx区): CPU side A0..A7 via
  1P/1N LS157 mux (BIT80, 256H, A5DES/A1DES/A0DES swap terms, 64H, AB4..AB7 —
  the schematic shows AB/64H etc mux -> A0..A7), /WROBJ write (SH5), /SABOBJ CPU select;
  data D-side to 1K LS245 -> DBB0..7 (CPU readback) and 1J LS241 -> HPLA0..7
  (object attribute stream to SH2/SH3).
- 2K LS157 + 3F LS08: A0DES/A1DES/A2DES/HHH1 generation from 2H/4H/8H/128H/HHH*
  (object slot sequencing).
- 3K LS377 + 3J LS374 + 4J LS373 + 4K LS175: HPLA pipeline latches: COL1..3 (3K),
  CF1..CF4 (3J outputs, SH1), PAP0..3 (4J, SH2), COL4..6 + HHHx (4K), LDCOL3H load.
- 4M? (LS86 4M pin11..13): HHH/8H XOR.
- 6H/3E buffers spread: BIT80, LPREPF, /ABLOAD (6M LS74 with /CNTLD, 6H).

## Sheet 5/5 — CN1 pinout, misc glue

CN1 (video <-> I/O), 50 pin:
 1..8 = DBB0..DBB7 (buffered CPU data), 9/20/25/27+ = gnd,
 10..19 = AB0..AB9, 21=B 22=G 23=R 24=/SYNC (video out to I/O board!),
 26=1Hµ (Z80 clock), 28=/VBLANK, 29=HBLANK, 30=/SABBKG, 31=HCMA, 32=/RDBKGH,
 34=/WRBKGH, 36=/RDOBJ, 38=/RDBKGL, 40=/WRBKGL, 42=/WROBJ, 43(47..50)=VCC,
 44=VCMA, 46=/SABOBJ.
- 9C LS153 dual 4:1 mux: HHH1, HCMP1 selected by SELECT/256Hx -> with /YA //YB and
  5F LS00 gates -> S0T1, S1T1, S0T2, S1T2 (SH2 shifter phase selects).
- 8A LS08 + 8E/6H buffers -> HCMP11, HCMP12 (SH3), HCMP21, HCMP22 (SH4).
- 9B LS175: BKB1/BKB2 (SH2, attr nibble bits) latched by /LD1 -> BK1, BK2 (SH1
  palette bank).
- 6P LS74: ABVIDOUT (SH4) resampled by 6MHz -> /VIDOUT (SH1, palette latch /OE).

## MAME cross-check notes

- MAME `screen.set_raw(18.432/3, 384, 0, 256, 264, 16, 240)`: 384×264 total matches
  an H chain to 256H+HBLANK (128 blank clocks) and V chain 264 lines, VBLANK rows
  240..255+16. To verify exactly once counters' preset values are transcribed.
- LS259 3G on the I/O board (MAME "mainlatch") drives VCMA (flip V... MAME flip_screen_x)
  and HCMA — naming crossed vs MAME's x/y; schematic VCMA goes to V XORs (SH1) via CN1-44.
- The 2× 82S100 PLAs 8C/8N are MAME's `proms2` NO_DUMP entries — their equations are
  the undumped part of the object priority/colour mixing. Behaviour must be inferred
  from MAME's draw order (spriteram2[+0x20] section priorities) + game observation.
- 6J/6K "CONTROL LOGIC" customs: likely PAL/HAL-class parts, undumped; their function
  (object fetch scheduling, collision COLL1) must be modelled behaviourally.
