# T80 instruction timing simunit

This simunit assesses instruction T-state totals and selected architectural effects for the Verilog simulation implementation `T80s.v`. It uses the Zilog *Z80 CPU User Manual*, UM008011-0816, as the timing oracle: https://www.zilog.com/docs/z80/um0080.pdf. `manifest.csv` is regenerated by `generate.py`; each row records the encoded bytes, expected T-states, classification, and manual page reference. `check_inventory.py` compares documented canonical encodings against an independently enumerated set, and fails initialization if the sets or classifications diverge.

The invariant inventory contains 698 distinct documented encodings: 252 base, 248 CB, 58 ED, 39 DD, 39 FD, 31 DD-CB, and 31 FD-CB. The test executes 1,325 generated vector rows: 643 rows classified as documented and 682 supplemental alias/undocumented rows. These are row counts, so operands and repeated prefix aliases can produce multiple rows for one encoding; the custom directed cases also execute documented flow and stateful operations. The inventory check, rather than the vector-row total, is the gate for complete documented-encoding classification.

The directed timing checks measure all 56 conditional JR/JP/CALL/RET outcomes, three DJNZ counter paths, 13 base unconditional transfers (JP nn, CALL nn, RET, JP (HL), JR e, and the eight RST targets), and two indexed JP(IX/IY) transfers. All eight repeating block instructions are tested for continuation and termination, including CPIR/CPDR equality exits with BC=1 and BC=2, state updates, transfer data, and I/O transaction count/address/data. A bounded BC=0 observation checks the first iteration's counter wrap and repeat behavior. Selected effects cover all eight ALU classes, DAA, CB rotate/shift/BIT, RLD/RRD, EX DE,HL, stack byte order, indexed memory, and representative control-flow targets.

The common prelude runs `OR A` to initialize flags because T80 reset does not initialize F. Memory uses JTFRAME's synchronous `jtframe_ram` helper; the testbench clocks its read on the falling master-clock edge so DI settles before T80 samples it on the rising edge. T-state totals are measured in master-clock edges with `CEN=1`; WAIT, interrupt, NMI, and BUSRQ inputs remain inactive in this timing suite.

Run the test or the T80-focused aggregate from the repository root:

```sh
source setprj.sh
simunit.sh --run modules/jtframe/ver/cpu/t80_timing
simunit-all.sh --only T80s
```

To emit replay traces, source the project environment and run the shared suite-capture script from the repository root:

```sh
source setprj.sh
modules/jtframe/ver/cpu/t80_equivalence/capture_suites.sh --out tasks/jtcores-150/artifacts
```

The timing test accepts the Icarus plusarg `+TRACE=/absolute/path/to/trace.csv`. Each row records sampled inputs at a rising master-clock edge and public T80s outputs after a 1 ns settle; the 19-column schema is `master_edge,RESET_n,CEN,WAIT_n,INT_n,NMI_n,BUSRQ_n,OUT0,DI,M1_n,MREQ_n,IORQ_n,RD_n,WR_n,RFSH_n,HALT_n,BUSAK_n,A,DOUT`.

The suite deliberately does not run a full 65,536-iteration zero-count repeat, cover `OUT0=1`, or exhaustively check arithmetic operands and asynchronous bus conditions. Its results establish the tested timing paths and selected effects; they do not establish exhaustive functional fidelity for every instruction input.
