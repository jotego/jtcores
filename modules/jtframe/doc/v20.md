# V20 byte-bus adapter

`cfg/cpu/jtframe_v20.yaml` selects `jtframe_v20`, an 8-bit transaction
interface around the existing nuV30 execution engine. It is shared JTFRAME
CPU support and has no game dependencies. It supports the native-mode
instruction subset implemented by nuV30; it is not a complete or cycle-accurate
replacement for NEC V20 silicon.

## Integration

Include `jtframe_v20.yaml` from `jtframe` with `from: cpu` in the core's
file list. Supply the existing nuV30 microcode tables through `HEXDIR`,
including the trailing slash when it is nonempty. The configuration reuses
`jtframe_v30.yaml`, including its synthesis QIP.

`clk`, active-high synchronous `rst`, `cen`, `cenb`, active-low interrupt
inputs and `poll_n` have the same contracts as `jtframe_v30`. There must be
one `cenb` between consecutive `cen` pulses, without overlap. Neither enable
is gated by the adapter. Interrupt sampling continues while bytes wait.

The external bus is a synchronous request/response interface:

| Signal | Contract |
| --- | --- |
| `A[19:0]` | Byte address, stable throughout a request |
| `dout[7:0]`, `din[7:0]` | Write byte and read byte |
| `req` | A byte transfer is pending |
| `rd_n`, `wr_n` | Active-low direction, qualified by `req` |
| `ready` | Accept the pending byte at a rising `clk` with `cen && req && ready` |
| `bs[2:0]` | Captured transaction kind: 0 INTA, 1 I/O read, 2 I/O write, 4 fetch, 5 memory read, 6 memory write |
| `qs[1:0]` | Inherited execution engine queue status |
| `buslock_n` | Inherited output; currently always high, see limitations |

Perform memory and I/O side effects once per accepted byte. A request remains
asserted during waits and when `cen` is low. The address, direction, kind and
write byte remain stable; `din` must be valid at acceptance. `ready` may remain
high. There is a `cen` interval with `req` low between consecutive bytes.
`bs` describes the last captured transaction until the internal cycle ends,
then becomes 7; only `req` qualifies external transfers. It does not reproduce
silicon's early status announcements or HALT status.

Aligned V30 words become two byte requests, low address first. Odd byte
accesses use the V30 upper lane. Odd words are already split by the V30 BIU;
the adapter preserves each address, including segment-offset and physical
address wrap. Reads are assembled into the original V30 lanes. Each INTA
cycle produces exactly one byte request, irrespective of UBE; the interrupt
controller must supply the vector on the second acknowledge. Reset masks
requests immediately and clears pending transactions at the next fabric edge.
It cannot undo an already accepted write.

The bridge returns READY only after all bytes complete. With no data phase it
returns READY immediately, allowing HALT housekeeping to finish. The shared
V30 wrapper also gains an optional `wr_n` output, derived from the owning
BIU's T2/T3/Tw phase. Existing named-port users may leave it open. No execution
or synthesized V30 state transitions change. The BIU's announcement-age
assertion permits saturation while an owning data phase is waiting; its
existing saturating counter and expiry logic are unchanged.

## Compatibility boundaries

* Execution and prefetch remain V30 behavior. The engine has a six-byte queue
  and word prefetches; a V20 has a four-byte queue and byte prefetches. Extra
  speculative fetches, self-modifying code visibility and exact instruction,
  bus, wait and interrupt timing are not V20-accurate. The byte interface is
  not a multiplexed V20/8288 pin-level bus.
* V20-specific instruction/flag behavior is not introduced by this wrapper.
  The local MAME NEC reference distinguishes V20/V30 behavior for TEST1 flags,
  decimal and ASCII adjusts, packed decimal operations, shifts/rotates,
  AAM/AAD, and some opcode aliases. These need execution-engine changes and
  independent V20 validation; passing the program below does not establish
  compatibility for those cases or arbitrary V20 software.
* nuV30 identifies the 8080 loader/BRKEM path as unimplemented. BRKEM, RETEM,
  CALLN and 8080 emulation are unsupported by this adapter.
* BUSLOCK is tied inactive by nuV30. LOCK-prefixed arithmetic can execute,
  but external bus exclusion is not implemented. There is no HOLD/HLDA
  interface. Use with a single bus owner; DMA arbitration requires additional
  CPU/BIU work.
* No complete hardware-derived V20 instruction suite, FPGA timing closure,
  resource measurement or physical V20 bus comparison has been run here.

The behavioral reference reviewed in place is MAME's
`src/devices/cpu/nec/nec.cpp` and `necinstr.hxx`; no MAME source is copied.
NEC's [V20/V30 user's manual](https://www.dosdays.co.uk/media/nec/NEC-V20-V30-Users-Manual.pdf)
is the hardware reference for further compatibility work.

## Maintained verification

From the repository root:

```sh
modules/jtframe/ver/cpu/v20/run.sh
```

This uses the locally installed `jotego/linter:latest` Docker image with
`--pull=never`; `SIM_IMAGE` can select another installed image with Go,
Icarus, Verilator and a C++ toolchain. Builds and logs remain in the ignored
`ver/cpu/v20/build/` and `logs/` folders.

`ver/cpu/v20_bus/.simunit` registers the suite with the normal unit matrix.
Its supported `init.go` hook runs the CPU program using Verilator, then the
unchanged simunit runner lints and executes the bridge with Icarus. The
nuV30 sources currently exceed Icarus's elaboration support; they are not
rewritten or stubbed to make this test pass. The normal Docker
`devops/xsimunit.sh` entrypoint exercises both levels, without workflow changes.

The bridge test checks 97 lane/kind/wait combinations, ordered word bytes,
stable captured transactions despite upstream announcements, paused enables,
no duplicate requests, partial-word completion prevention, single-byte INTA,
HALT readiness, reset cancellation and rearming.

`ver/cpu/v20/program.hex` is a hand-encoded native-mode program with instruction
annotations. `cpu_test.sv` checks fixed expected results and side-effect counts,
not output captured from this CPU. It boots at FFFF0 and exercises even/odd
memory words, 20-bit and segment-offset wrap, arithmetic, REP MOVSB, NEC SET1,
even/odd word IN/OUT, software interrupts, two-cycle maskable INTA, NMI,
stack/IRET, both interrupt wakes from HLT and WAIT/POLL. LOCK-prefixed INC
checks its arithmetic only, not bus exclusion.

The program runs through the V20 wrapper, the original 16-bit V30 wrapper,
and the V20 wrapper compiled with `SYNTHESIS`, each with zero and deterministically
varied waits up to 3 and 16 enable periods. Source assertions are enabled.
A corrupt-read negative control must fail the fixed arithmetic result check.
The V30 memory model retains the owning address/kind after status release,
matching the de-multiplexed V30 bus contract. These are targeted regressions,
not a complete V20 or V30 instruction qualification.
